# Вход в VK из браузера на VPS

Эта временная среда нужна для ручного входа владельца с IP VPS. Она не подключает
каталог VK к WAVE, не выполняет поиск и не подтверждает доступность полного аудио.
Успешный вход и воспроизведение в браузере нужно проверить отдельно.

Предварительно установлены `google-chrome`, `xvfb`, `x11vnc`, `novnc`, `websockify`,
`xauth`, `openbox` и `dbus-run-session`. На VPS пользователя доступны 3.8 ГиБ RAM
и 35 ГиБ диска; порты 5900 и 6080 перед установкой были свободны.

1. На Mac в отдельном терминале подключитесь к VPS с туннелем и оставьте окно
   открытым:

   ```sh
   ssh -o ExitOnForwardFailure=yes -L 6080:127.0.0.1:6080 root@13.143.249.62
   ```

2. На сервере:

   ```sh
   cd /opt/wave
   git pull --ff-only origin main
   python3 scripts/vk-browser.py start
   ```

   Первый запуск попросит отдельный пароль VNC (8 символов, ввод скрыт), повтор
   пароля и подтверждение сохранения `y`. Не используйте пароль VK. Пароль не
   передаётся в командной строке и не отправляется в чат.

3. После сообщения «Готово» в обычном Chrome на Mac откройте:

   ```text
   http://127.0.0.1:6080/vnc.html?autoconnect=true&resize=scale&path=websockify
   ```

   Введите пароль VNC. Откроется окно Chrome на сервере. Вход VK, SMS, QR или
   другое штатное подтверждение выполняйте самостоятельно внутри этого окна.
   Не присылайте пароль, код, QR входа или Cookie. Проверьте поиск и прослушивание
   песни в этом браузере. Антибот-проверки не обходятся и успех входа не обещается.

4. После проверки остановите временный браузер:

   ```sh
   cd /opt/wave
   python3 scripts/vk-browser.py stop
   ```

Браузер работает отдельным непривилегированным пользователем `wave-vk` без shell.
Профиль и вход находятся в закрытом `/var/lib/wave-vk/profile` (0700 на родительской
папке). Файл VNC-пароля приватный. Остановка сохраняет профиль, не удаляет учётную
запись и программы; при необходимости отзовите вход в настройках безопасности VK.
Профиль не входит в git и не копируется в среду Codex. Доступа к `/etc/wave.env`
этому пользователю не предоставляется.

Xvfb использует Xauthority и не слушает TCP. VNC и noVNC слушают только IPv4
loopback на VPS. Nginx, внешние порты и firewall не перенастраиваются.
Доступ с Mac идёт через SSH; открывать 5900/6080 наружу нельзя. Служба временная,
не добавляется в автозапуск, останавливается через 2 часа. Ограничена 1536 МиБ
RAM и 512 задачами. Песочница Chrome и проверка TLS не отключаются.

`systemd` здесь требуется для запуска. Владелец уже подтвердил запуск окна, вход
VK и движение воспроизведения в первоначальной версии. Новый приватный канал
поиска ещё нужно проверить на VPS. Вход в браузере не подтверждает API-доступ
из WAVE. Локальные проверки:

```sh
python3 tests/vk-browser.test.py
node tests/vk-browser-driver.test.mjs
```

При ошибке скрипт выводит последние сообщения собственной службы. Логи дочерних
процессов не печатаются: из них выводятся только фиксированные категории ошибок.
Нельзя отправлять полный браузерный профиль или необработанные логи с VK URL.

## Проверка поиска внутри серверного браузера

Для чтения из вошедшего браузера добавлен администраторский канал. Chrome
запускается с `--remote-debugging-pipe`: команды идут по унаследованным каналам
процесса, порт отладки не открывается. Ограниченный интерфейс проверки доступен
только по Unix-сокету `/run/wave-vk-browser/control.sock` с правами 0600 внутри
папки 0700. Ему доступны root и владелец процесса `wave-vk`; обычным пользователям
приложения и самому backend WAVE доступ не выдаётся.

После обновления кода нужно один раз перезапустить только временный браузер:

```sh
python3 scripts/vk-browser.py restart
node scripts/check-vk-browser.mjs --user-id 74487404 --query Queen
```

Профиль сохраняется. Если VK снова потребует вход, выполните его самостоятельно
через защищённое окно и повторите проверку. Cookie не копируются и не читаются
скриптом. Первая проверка прямого `al_audio.php` вернула посторонний популярный
список на Queen и неполные названия. Она не подтвердила поиск; HTTP 200 и
`ok:true` того прототипа нельзя считать успехом подключения.

Теперь проверка открывает штатную страницу `/audiosID?q=…` в том же браузере
и читает отображаемые музыкальные строки. Названия берутся из текста интерфейса,
без декодирования неизвестного ответа старого API. Запрос должен совпасть с URL
страницы; посторонние треки исключаются по исполнителю/названию, совпадение
исполнителя ранжируется первым. При отсутствии совпадений возвращается ошибка,
а не успешная чужая подборка. Количество `received` означает число просмотренных
элементов DOM, не размер каталога VK. `matched` — число подходящих строк.
Если нужная выдача уже открыта, проверка читает её без перезагрузки. Иначе она
обновит страницу музыки, поэтому текущее воспроизведение может прерваться.
Перенаправления на вход и проверки безопасности не обходятся.
Результат содержит до восьми названий, исполнителей и длительностей или
фиксированный код ошибки. Строка `playback_verified:false` намеренно означает,
что даже успешный поиск ещё не доказывает полный аудиопоток для WAVE.

Скрин владельца подтвердил: выдача Queen на странице есть, а старые CSS-селекторы
не находят строки. Добавлены современные имена классов/атрибутов и чтение открытых
Shadow DOM, а также iframe музыки того же origin. Если строки не распознаны,
`layout` содержит ограниченные цепочки тегов, CSS-классов и testid вокруг только
четырёх известных публичных названий/имён. Ссылки, атрибуты авторизации, формы
входа, произвольные тексты и HTML страницы не экспортируются. Это диагностика
структуры музыкальных карточек, не снимок личного профиля или переписки.

После установки этой версии ещё нужен один перезапуск браузера. Затем изменения
самого `scripts/vk-browser-layout.mjs` подхватываются при следующей проверке без
перезапуска Chrome. Файл кода принадлежит root в checkout, служба имеет доступ
только на чтение; произвольный код через администраторский запрос не принимается.

Для проверки после перезапуска откройте удалённое окно, введите Queen в поиске
музыки, нажмите «Найти» и дождитесь списка песен. Потом запустите только
`node scripts/check-vk-browser.mjs --user-id 74487404 --query Queen`.

Новый отчёт владельца находит только `TopAudioPlayer_Title`; отсутствие строк
пока не доказывает, что их нет в DOM или что виноват iframe. Добавлены варианты
camelCase testid (`AudioRow`/`AudioItem`) без привязки к обфусцированным CSS-классам.
При ошибке диагностика теперь содержит известные музыкальные testid и имена
музыкальных custom elements, а для iframe — только разрешённое имя хоста,
категорию пути и доступность документа. Query/fragment iframe и приватные поля
форм не печатаются. Эта правка модуля разметки не требует перезапуска браузера.

Следующий живой ответ прочитал названия, но потерял исполнителей: появились
только совпадения слова Queen в названиях чужих песен. Такой результат не
подтверждает полноценный поиск. Чтение теперь объединяет заголовок с ближайшей
карточкой с исполнителем/подзаголовком и длительностью, не пересекая заголовок
другой песни. Результаты с пустым исполнителем исключаются и помечаются как
`incomplete_track_metadata`, если полных записей нет. Исполнитель никогда не
подставляется из поискового запроса. Требуется новый живой ответ после обновления
этого модуля; перезапуск Chrome не нужен.

Локально проверены границы доступа, отбрасывание чужой популярной подборки и фрагментация
канала. Отдельно проверен настоящий Chromium с одноразовым пустым профилем:
команды через pipe и чтение кириллических названий из DOM в `about:blank` работают. Локальная
проверка выполнялась без sandbox только из-за ограничений тестового контейнера;
в запуске VPS песочница остаётся включённой. Эти проверки не содержали входа VK.

Дополнительно наблюдаются ограниченные сведения о запросах/ответах аудио/поиска:
название метода, HTTP-статус, тип содержимого, известные имена полей запроса и
фиксированные значения действия/раздела. Значения query, hash, owner_id и токенов
не экспортируются наблюдателем; разрешён только сам переданный оператором запрос
в отчёте результатов. Полные URL, заголовки, Cookie,
токены, хэши и тела ответов не экспортируются. Для просмотра таких сведений после
ручного поиска/воспроизведения в окне:

```sh
node scripts/check-vk-browser.mjs --status
```

Проверка не включает источник в WAVE, не меняет `/etc/wave.env`, не распространяет
музыку другим пользователям и не превращает личную сессию в массовый API.
