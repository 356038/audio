# Продолжение WAVE на VPS — 3 ноября 2026

Этот файл передаёт контекст облачного чата в Codex CLI на сервере. Пользователь
хочет, чтобы агент сам выполнял команды и довёл подключение поиска музыки VK
до проверенного результата. Общаться по-русски, кратко. Не просить пользователя
вручную выполнять доступные агенту команды. Ввод паролей, SMS/QR и подтверждения
входа выполняет только сам пользователь.

## Сервер и действующее приложение

- Checkout: `/opt/wave`, origin `https://github.com/356038/audio.git`, основная
  ветка `main`. Перед работой проверить текущий HEAD и `git status`; сохранить
  любые локальные изменения. Не делать `reset --hard`/очистку пользовательских файлов.
- Ubuntu 26.04 amd64, Node 22.22.1, около 3.8 ГиБ RAM и 35 ГиБ свободного диска
  на момент проверки. Публичный IP `13.143.249.62`.
- Плеер: `https://wave-player-test.duckdns.org`, systemd `wave.service`, nginx
  перед Node на `127.0.0.1:8787`. Не перезапускать другие проекты/службы.
- Секреты действующего плеера — `/etc/wave.env`, только root. Не выводить файл,
  токены, Cookie, подписанные URL и полное окружение в чат, git или логи.
- Библиотека и история — `/var/lib/wave/library.sqlite`; не удалять их при
  очистке аудиокэша. Чужую личную музыку не превращать в общий каталог.
- Telegram-профиль и Audius уже работают. Internet Archive удалён по просьбе
  пользователя в `153a28e`; не возвращать его и подписи лицензий под треками.
- Существующие темы, полноэкранный плеер, сохранения, рекомендации и локализация
  должны продолжить работать. Не менять дизайн в рамках подключения VK.

## Почему понадобился Codex CLI

Облачный чат не получил SSH TCP-гранты, хотя Tailscale был настроен. В доступном
пользователю интерфейсе есть только поле ключа. Запуск CLI на VPS даёт отдельному
сеансу прямой локальный доступ к проекту. Это не перенос соединения в старый чат;
CLI не имеет его истории автоматически — используйте этот файл и код проекта.
GitHub-аутентификация облачной среды не переносится на VPS. Проверять доступ
обычными инструментами; не просить секреты в чат и не обещать push без проверки.

## Что уже проверено с VK

- Пользователь разрешил ограниченный эксперимент со своим действующим аккаунтом:
  отдельный аккаунт зарегистрировать не удалось. Логин выполнен лично владельцем
  в Chrome непосредственно на VPS. Он подтвердил поиск Queen и движение времени
  воспроизведения. VNC не передаёт звук на Mac.
- Перенос Cookie из Mac в Python HTTP-клиент не подтвердил вход: были переходы
  на мобильную версию и затем на login.vk.ru. Не повторять старый путь по кругу.
- Текущий путь: авторизованный браузер + приватный канал Chrome, без копирования
  Cookie, токенов сторонних приложений, обхода проверок входа или DRM.
- Нет подтверждённого бесплатного анонимного поиска VK «по одному IP». Браузерный
  эксперимент не доказывает возможность обслуживания 10–100 тысяч пользователей.

## Временный браузер и проверка

Прочитать `deploy/vk-browser.md`, затем `scripts/vk-browser.py`,
`scripts/vk-browser-driver.mjs`, `scripts/vk-browser-layout.mjs` и
`scripts/check-vk-browser.mjs`.

- Google Chrome 156.0.8078.79 установлен с официального сайта Google. Также есть
  Xvfb, x11vnc, noVNC/websockify, xauth, openbox, dbus-run-session.
- Пользователь браузера `wave-vk`, профиль `/var/lib/wave-vk/profile`, закрытые
  права. Пароль VNC хранится отдельно; не показывать/расшифровывать его.
- Служба `wave-vk-browser.service` временная, останавливается через 2 часа.
  На следующий день она может уже не работать. Профиль переживает остановку.
- Проверить `python3 scripts/vk-browser.py status`; при необходимости выполнить
  `python3 scripts/vk-browser.py start`. Не перезапускать работающий браузер без
  причины: это обрывает VNC. Изменения только layout-модуля подхватываются горячо.
- 5900 и 6080 слушают loopback. Не публиковать их в nginx и не открывать наружу.
  На Mac пользователь уже запускал SSH-туннель в фоне:
  `ssh -fNT -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -o ServerAliveCountMax=3 -L 127.0.0.1:6080:127.0.0.1:6080 root@13.143.249.62`.
  Пользователь открывает noVNC на локальном порту 6080 и сам проходит вход.
- Chrome control использует `--remote-debugging-pipe`, не TCP-порт отладки.
  Администраторский HTTP работает только по Unix-сокету
  `/run/wave-vk-browser/control.sock` (0600, родитель 0700). Backend `wave` пока
  не получает к нему доступ. Песочницу Chrome и TLS не отключать.

## Последний живой результат и оставшаяся задача

Последняя применённая пользователем версия сборщика — `0fcba29`.
Команда на VPS:

```sh
cd /opt/wave
node scripts/check-vk-browser.mjs --user-id 74487404 --query Queen
```

Она получила `ok:true`, `received:290` (элементы DOM, не число песен каталога),
`parsed_rows:179`, `blank_titles:53`, `missing_artist:0`, `matched:21`.
В первых восьми записях исполнитель Queen, правильные названия, но `duration:0`.
ID: `74487404_456239116`, `74487404_456239117`, `74487404_456239106`,
`74487404_456239105`, `74487404_456239107`, `74487404_456239118`,
`74487404_456239120`, `74487404_456239119`. Это namespace аккаунта пользователя;
нужно отделить «Мои треки» от общего поиска. Проверка «Король и Шут» предложена,
но её живого результата в старом чате ещё нет.

`playback_verified:false` — это существенное ограничение. Наблюдения HTTP 206
audio/mpeg относятся к браузеру, не к воспроизведению через WAVE. Рабочий VK
provider в WAVE НЕ подключён: не объявлять задачу выполненной по этому отчёту.

Сначала самостоятельно воспроизвести результат, проверить второй запрос,
правильно выделить исполнителя/название/длительность/ID и общедоступный раздел.
Затем проверить получение реальных аудиобайтов и Range для выбранного результата.
Не подставлять исполнителя из запроса и не считать постороннюю подборку успехом.
Не показывать в выдаче пустые/неполные треки как готовые к прослушиванию.

Подключение к API WAVE делать после живой проверки. Сохранить Telegram-аутентификацию,
пользовательские подписанные stream tickets, приватность учётной записи VK,
проверку адресов источника и ограничения кэша. Сохранения должны переживать
перезапуск; ошибки/истечение сессии не должны маскироваться пустой выдачей.
Не включать массовую выдачу личной коллекции аккаунта и не обещать нагрузку без замеров.

## Проверки и завершение

Для инструментария браузера:

```sh
python3 tests/vk-browser.test.py
node tests/vk-browser-driver.test.mjs
```

До изменения production запустить подходящие тесты из `tests/*.test.mjs`;
после изменения API проверить реальные поиск, воспроизведение, переключение,
перемотку и сохранение. Искусственные ответы тестов не заменяют live-проверку.
Сохранить изменения в git. Если нужны права push, установить их через штатный
вход владельца в GitHub, без пересылки токенов. Перезапускать только `wave`
после успешных проверок и проверять `/health`.
