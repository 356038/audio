# Проверка VK через текущий вход браузера

Это отдельная проверка поиска, не включение VK в плеере. Пароль, SMS-коды,
токен чужого приложения и установка расширений не нужны. Скрипт использует
текущую сессию вашего VK, делает ограниченные запросы просмотра/поиска,
не записывает сессию на диск и не меняет `/etc/wave.env` или библиотеку.

Cookie даёт доступ к вашему аккаунту: вставляйте его только в скрытый запрос
скрипта на своём сервере. Не отправляйте его в чат, не вставляйте в команду
оболочки и не показывайте на скриншоте. После проверки можно отозвать
соответствующий сеанс в настройках безопасности VK.

## Получение своей сессии

1. В Chrome на своём компьютере откройте музыку VK и войдите обычным способом.
   Проверьте, что песня играет. Запомните домен в адресной строке: `vk.ru`
   или `vk.com`.
2. Откройте инструменты разработчика: **⌥⌘I** на Mac. Выберите **Network / Сеть**.
3. Найдите `Queen` в поиске музыки VK. Среди запросов выберите запрос на
   `al_audio.php` того же сайта. В **Headers / Заголовки → Request Headers /
   Заголовки запроса** найдите **Cookie** и скопируйте только его значение.
   Не копируйте `Set-Cookie` из ответа и не используйте Copy as cURL.
4. В терминале своего VPS запустите:

   ```sh
   cd /opt/wave
   git pull --ff-only origin main
   python3 scripts/check-vk-session.py --host vk.ru
   ```

   Если сайт в браузере открыт на `vk.com`, замените `--host vk.ru` на
   `--host vk.com`. Скрипт не переносит Cookie при перенаправлении на другой
   сайт. Удалённые адреса фиксированы, TLS проверяется обычным способом.
5. Вставьте Cookie в приглашение **«Cookie VK (ввод скрыт)»** и нажмите Enter.
   Во время вставки символы не отображаются — это ожидаемо. Скрипт печатает
   только число результатов и до восьми названий, исполнителей и длительностей.
   Этот вывод можно прислать в чат. Сам Cookie не присылайте.

Если скрипт не распознал текущий ID, можно повторить с
`--user-id ЧИСЛОВОЙ_ID_ВАШЕГО_АККАУНТА`. Это ID своего профиля, не ID группы
или трека. При отсутствии `al_audio.php`, изменившемся формате ответа,
перенаправлении на вход или HTTP 401/403/429 проверка останавливается.
Не нужно вручную обходить проверки VK или повторять запросы циклом.

VK может потребовать подтверждения сессии при обращении с нового IP сервера.
Скрипт не выполняет вход, не решает капчу и не обещает, что перенос браузерной
сессии будет принят. Пока нет успешного ответа с VPS, доступ не подтверждён.
Даже успешный поиск не доказывает доступность полного аудио — это следующий
отдельный этап перед подключением к WAVE.

## Проверки разработки

```sh
python3 tests/vk-session.test.py
```

Используются искусственные ответы: проверяются ограничение размера, формат
поиска, запрет перенаправлений, скрытие секретов и исключение подмены адреса.
Живой вход VK этими проверками не подтверждается.
